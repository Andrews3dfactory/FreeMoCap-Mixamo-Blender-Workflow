# Contributing

Thanks for helping improve this community guide. Corrections, clearer steps, accessibility fixes, and verified screenshots are welcome.

## Before proposing a change

- Check the current guide and search existing issues for duplicate reports.
- Keep instructions specific to verified software versions; call out version-dependent behavior.
- Do not present placeholder illustrations as real application screenshots.
- Preserve the dependency-free static-site setup used by GitHub Pages.

## Make and verify your change

1. Fork the repository and create a focused branch.
2. Edit the existing HTML, CSS, JavaScript, or documentation rather than adding a build dependency.
3. Check changed pages at mobile and desktop widths, and test navigation, keyboard focus, and reduced-motion behavior where relevant.
4. Verify internal links, fragments, and image paths. Keep descriptive alternative text for informative images.
5. Open a pull request describing what changed and how you checked it. Include the relevant application version for interface instructions or screenshots.

## Screenshots and licensing

Only contribute screenshots you have permission to share. Identify the application and version, redact personal information, and add a useful caption and alternative text. Project guide content is shared under the license in [`LICENSE`](LICENSE); verify image or third-party asset rights separately before contributing them.

## Reporting a problem

Use the repository's GitHub Issues to report incorrect steps or compatibility problems. Include your operating system, application versions, the expected behavior, and the actual result. Remove personal information from logs and screenshots.
