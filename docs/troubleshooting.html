Troubleshooting

Start with the exact error and the step where it occurred. Keep original video and session data safe while investigating.

Windows·Version-aware checks

FreeMoCap, Blender, and FFmpeg interfaces and supported formats change. Check the official docs for your installed release and include software versions when seeking help.

FFmpeg not found

Check that FFmpeg is on PATH

Open a new Command Prompt and run:

where ffmpeg
ffmpeg -version

If no executable is found, make sure PATH contains the folder with ffmpeg.exe (commonly C:\ffmpeg\bin), then close and reopen the terminal. See FFmpeg setup.

Video import failure

FreeMoCap will not load the video
  • Check that the transfer completed and the clip plays in a local media player.
  • Use the original iPhone video if your FreeMoCap version supports the container and codec. Otherwise, convert a copy to H.264 MP4 with the conversion guide.
  • Keep the original file and choose the documented existing-video workflow for your version; UI labels can differ.
  • For multi-camera reconstruction, check that source files belong to one synchronized recording and use matching calibration.

Calibration issues

Calibration reports failure or poor results
  • Confirm the printed ChArUco layout and dimensions match the configuration selected in FreeMoCap.
  • Keep the target sharp, unobstructed, and visible to all required cameras.
  • Secure cameras so they do not move after calibration.
  • For ground-plane calibration, follow the version-specific initial-board placement and stillness instructions.
  • Not every single-camera test needs multi-camera calibration.

Tracking quality problems

Body landmarks are missing or jittery
  • Prefer original footage at 1080p or higher and 30–60 FPS when practical; avoid heavy compression and motion blur.
  • Use even lighting, a stable camera, a clean background, and full-body framing.
  • Reduce occlusion and try a short, simple motion.
  • Review calibration and camera coverage if using multiple cameras.

Converting an existing low-resolution video cannot restore missing details.

Blender import or export problems

No Blender scene or unexpected output format
  • Check Blender detection and the FreeMoCap release's documented compatibility with your Blender version.
  • Verify that the selected detector supports that release's Blender exporter. Upstream's current integrated exporter documents MediaPipe output support; compatibility may change.
  • Do not assume every release creates a .blend, FBX, or BVH. Check the format actually produced.
  • A raw skeleton data file is not necessarily a Blender animation scene. Preserve the recording folder and full error message.

Retargeting issues

Character twists, drifts, or does not animate
  • Confirm the source motion plays before retargeting.
  • Use a retargeting tool that supports your Blender version and both skeletons. Rokoko add-on compatibility with FreeMoCap data is not assumed; verify current tool documentation.
  • Check bone mapping, rest pose, root motion, scale, and forward/up axes.
  • Inspect the entire animation for foot sliding, floor penetration, and twisted limbs before baking.

Still stuck?

Include your Windows, FreeMoCap, Blender, and FFmpeg versions, the exact step that fails, and the complete error message. Share only recordings you have permission to share, and remove personal information from screenshots and logs.
